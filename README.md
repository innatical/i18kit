# i18kit

i18kit is a small toolkit for translating TypeScript projects. You wrap your strings in `t()` calls, a CLI collects them into a gettext template, you translate them in a local web editor, and your app reads the resulting `.po` files at runtime.

Everything is stored as standard gettext files (`.pot` and `.po`), so your translations are never locked into i18kit. Any other gettext tool can open them.

There are three packages in this repo:

| Package | What it is |
| --- | --- |
| [`i18kit`](packages/cli) | The CLI: `init`, `extract` and `open` |
| [`@i18kit/core`](packages/core) | The runtime library that loads `.po` files and translates strings |
| [`@i18kit/web`](packages/web) | The editor UI that `i18kit open` serves (not published on its own) |

## Quick start

Install the CLI globally and the runtime library in your project:

```sh
npm install -g i18kit
npm install @i18kit/core
```

From your project root, set things up:

```sh
i18kit init
```

This asks for a locales directory, a project name, a source language and the locales you want to support. It then scans your code, writes `locales/i18kit.pot`, and creates a `.i18kit.json` config file.

Use `t` in your code:

```ts
import { loadTranslations, createTranslator } from '@i18kit/core'

// once, at startup
await loadTranslations()

// per request, per user, whatever fits your app
const { t, tc } = createTranslator('fr')

t('Save changes')
t`Hello ${name}, you have ${count} new messages`
tc('menu', 'Open')
```

Run `i18kit extract` whenever you add or change strings, then translate them:

```sh
i18kit open
```

That starts the editor in your browser. Add a locale, sync it from the template, and fill in the translations. Changes are written straight to the `.po` files in your project.

## How strings work

Each string gets an id, which is a hash of the message plus its context (if any). The id is written into the `.pot` file as a comment and is what `@i18kit/core` uses to look translations up.

A few things follow from that:

- **Editing a source string makes it a new string.** If you change "Save changes" to "Save your changes", the old translations no longer match and the string shows up untranslated. This is on purpose, since the old translation was for different text.
- **Context separates identical strings.** `tc('menu', 'Open')` and `tc('door', 'Open')` are two entries, so they can be translated differently. `t('Open')` is a third.
- **Interpolated values become numbered placeholders.** `` t`Hello ${name}` `` is stored as `Hello {0}`, and the values are filled back in after translation. Translators can move the placeholders around but should not remove them.
- **Missing translations fall back gracefully.** If a string has no translation you get the source text. If you ask for `es-ES` and only `es.po` exists, `es` is used.

The extractor finds calls to `t` and `tc` in `.ts` and `.tsx` files, and skips `node_modules`, `.git` and `dist`. The message has to be a string literal or a template literal. A variable like `t(someString)` can't be extracted because the value isn't known until runtime.

`@i18kit/core` reads files with `fs`, so it is meant for Node and Bun, not for running in a browser.

## Project files

After `init` you will have something like this:

```
.i18kit.json
locales/
  i18kit.pot     the template, generated by i18kit extract
  fr.po          one file per locale
  de.po
```

`.i18kit.json` looks like this:

```json
{
  "name": "my-app",
  "sourceLanguage": "en",
  "locales": ["fr", "de"],
  "localesDir": "locales",
  "createdAt": "2026-05-09T19:37:01.268Z"
}
```

Commit all of it. The `.po` files are your translations.

## Commands

| Command | What it does |
| --- | --- |
| `i18kit init` | Interactive setup. Creates `.i18kit.json` and the first `.pot` file. |
| `i18kit extract [dir]` | Scans your code (or `dir`) and rewrites the `.pot` template. |
| `i18kit open` | Starts the local editor. Run it from a directory that has a `.i18kit.json`. |

`open` takes two options:

```
--port <n>    listen on a specific port instead of a random one
--no-open     print the link instead of launching a browser
```

## The editor

`i18kit open` starts a small server on your machine and opens the editor in your browser. Press Ctrl+C in the terminal to stop it.

In the editor you can browse the template and each locale with translation progress, search and filter entries (untranslated, fuzzy, translated), edit a translation and mark it fuzzy, and create or update a locale file from the template.

There is also a Generate button that fills in a translation using a provider. Google Translate, DeepL, OpenAI, Claude and Gemini are supported. Add an API key for the ones you use on the settings page, and pick a default. Keys are stored in `~/.config/i18kit/credentials.json`, readable only by you, and are never sent to the browser.

The server is only meant for you, so it is locked down:

- It listens on `127.0.0.1` only and rejects requests with an unexpected `Host` or `Origin` header.
- The link it prints contains a one-time code that the page trades for a session token. The code stops working after the first use, so the link in your terminal history is harmless.
- It can only read and write `.po`, `.pot` and `.i18kit.json` files inside the project directory. Paths that try to leave it, including through symlinks, are refused.

If you open a second tab or restart the server you will need a fresh link from `i18kit open`.

## Development

You need [Bun](https://bun.sh).

```sh
bun install
bun run build:cli     # builds the web UI, then bundles it into the CLI
```

To work on the editor with hot reload, run the server and the Vite dev server side by side. In your test project:

```sh
bun run /path/to/i18kit/packages/cli/src/index.tsx open --no-open --port 4173
```

Then, in `packages/web`:

```sh
I18KIT_API_URL=http://127.0.0.1:4173 bun run dev
```

Open the link printed by the first command, but swap the host and port for the Vite ones and keep the `#code=...` part.

The CLI's API lives in `packages/cli/src/server`. The UI talks to it through `packages/web/src/lib/local.ts`.
